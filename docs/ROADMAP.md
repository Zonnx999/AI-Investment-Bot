### 1.2 운영 관찰 (배포 뒤 — 코드 작성 없이 지켜보기)
이 라운드의 핵심 가설은 "검증 안 된 신호를 빼고 점수 체계를 하나로 하면 메시지가 읽을 만해진다" 와 "보낸 종목의 사후 성과를 재면 신호의 쓸모가 보인다" 입니다. 둘 다 시간이 필요합니다.
- **원장 판정**: 비중첩 20거래일 블록 6개(≈ 6개월) 가 쌓일 때까지 `⏳검증 전 (4주 구간 n/6)`. 판정 전환은 **월요일**에만. v1 규칙은 배포 뒤부터 새로 세므로 판정은 대략 배포 6개월 뒤. (07-13 소급분은 규칙 v0 이라 별도 구간.)
  주 1회 `/ledger us`·`/ledger kr` 로 추이만 확인, 숫자 하나에 반응하지 말 것(표본 리스트 1개).
- **첫 재점수 때 기록할 것**: 소요 시간·메모리(`MemoryPeak`) + journal 의 `init_sync=… elapsed=…s`(레플리카 미리 pull 소요 — 다이제스트 프로브 180초·`warm_replica` 타임아웃 1200초가 적정한지 판단하는 값, `DEPLOYMENT.md §10` 단계 6).
- **2주 뒤 점검 (KR 근소 교체, RVM-07)**: KR 일일 가격 갱신을 켠 뒤 6·7위가 근소한 점수차로 번갈아 교체되는지(= '매수 검토/탈락' 반복) 빈도를 보고 히스테리시스 도입 여부 결정 — 후보 §2 의 12번.
- **4주 뒤 점검**: US 저녁 메시지의 '변화 없음' 비율(결정 #1 재검토), 상태 줄 ⚠️ 빈도, 소유자 DM 이 오탐인지(헬스 임계 재조정), 재점수 타이머 실행 시간·메모리(`MemoryPeak`),
  `재보강 누락 종목`·`선정 후 수익률 이상치` DM 의 빈도와 원인(KR 은 4월 무렵 DART 대상 연도 전환 때 특히 — 임계 60%·7일의 적정성).
- **IC 정보 관찰**: 재점수마다 쌓이는 유니버스 스냅샷으로 `scripts/ledger.py ic` — 점수 순위와 이후 수익의 순위상관. 정보용이지 판정 근거 아님.
- **판정 결과에 따른 행동 규칙** (미리 정해 둠, 결과를 본 뒤 임의로 바꾸지 않기): `validated` → 문구에서 '검증 전' 만 제거, `demoted` → 후보 제목에 `검증 미달` 이 자동으로 붙음(결정 #9, 구현됨) → 점수 규칙 재설계 라운드, `testing` → 계속 관찰.

## 2. 다음 라운드 후보 (우선순위 제안 — 관찰 결과로 재정렬)

1. **시점 일관(PIT) 펀더멘털 하네스** — 재점수마다 쌓이는 스냅샷을 이용해 "그 시점에 알 수 있던 정보만"으로 점수 규칙을 되돌려 검증. 생존편향 없는 백테스트의 전제. (원장·스냅샷 인프라는 이미 있음)
2. **Turso API 캐시 로컬 분리 (OPS-06)** — 캐시 쓰기가 원격 왕복이라 재점수 시 `QUANT_BOT_CACHE=off` 가 강제됨. **서버에서 측정이 선행**(쓰기/읽기·로컬/원격 분리, `CLAUDE.md §4.10 (4)`).
3. **금융 전용 스코어카드** — ROA·NIM·자기자본비율 등. 지금은 미국 금융업을 50% 중립으로 처리해 자동 후보에서 거의 빠짐(결정 #4-B).
4. **국면 모델 개선** — 검증 프레임워크(`check_backtest`)에 올려 통과한 뒤에만.
5. **IC 기반 강등 + 메시지 검증 배지** — 신호별 IC 가 쌓이면 약한 신호 자동 강등, 메시지에 '검증됨/검증 전' 배지.
6. **대시보드 원장 탭** — 후보 리스트별 성과·블록 초과수익 시각화.
7. **isin/cusip 기반 증권 분류** — 이름·형제 규칙이 못 잡는 영구우선주(STRC 류) 대응.
8. **KR 업종 분류 + 다일 거래대금** — KRX 소속부 수준을 넘어 업종 상한·유동성 필터 강화.
9. **부트스트랩 메모리 최적화** — 1GB 박스에서 재점수 `MemoryMax=600M` 여유 확보.
10. **FMP bulk (플랜 확인 후)** — 현재 `key-metrics-ttm-bulk` 는 402. 플랜 한도가 확인되면 재점수 콜 수를 크게 줄일 수 있음.
11. **KR 배당 DART 연동** (구 백로그 잔여) — 현재 KR 배당 0 고정. DART 필드 라이브 검증 필요.
12. **KR 후보 히스테리시스 (RVM-07)** — 일일 가격 갱신(`quant-kr-refresh`)으로 6·7위가 근소한 점수차에서 번갈아 교체되면 '매수 검토/탈락' 이 반복됨. §1.2 의 2주 관찰 결과로 결정(예: 교체에 최소 점수차 또는 N일 유지 요구). 선정 규칙 변경이므로 `RULE_VERSION` 상향 대상.
13. **`requirements.lock` 해시 고정** — 지금은 버전만 고정. `uv pip compile --generate-hashes` + `pip install --require-hashes` 로 재현성에 더해 변조까지 막음. 서버 의존성 결정(#6) 뒤에.
14. **점수 입력 조립 공용 헬퍼** — 유니버스 경로(`universe._compute_enrich` 의 quote shim·금융 판정·배당)와 수동 경로(`screen_one`·`factor_scores`)가 입력을 따로 조립해 어긋나기 쉬움
    (`CLAUDE.md §4.10 (6)` 의 shim 사고, 이번 라운드의 수동 경로 금융·배당 불일치). 하나로 일원화 — 점수가 안 바뀌는 리팩터링이므로 기존 점수를 고정하는 테스트가 선행.
15. **선정 후 이상치 임계(60%) 재검토** — `SINCE_ABS_MAX_PCT` 는 첫 가정값. 알림이 실제로 잡은 사례(분할 미반영 vs 진짜 급락)를 보고 조정. 알림 임계표와 마찬가지로 원장 데이터가 쌓인 뒤에.

> 공통 규칙: 점수·필터·정렬 규칙을 바꾸는 항목은 `universe.RULE_VERSION` 을 올리고(`CLAUDE.md §4.10 (20)`), 새 선택 기능은 실패가 헬스로 올라가는 경로를 먼저 정한다(`(15)`).

## 3. 상용화 전환 (Phase A→E) — **보류** (2026-10 결정 #10)

> **보류 사유**: 신호의 실효성이 아직 검증되지 않았습니다(선행지표 통과 0/7, 후보 성과는 원장 판정 대기). 검증 전에 사용자를 늘리면 North Star(30일 리텐션) 목표와 충돌합니다 —
> 실효성 없는 메시지를 받은 사용자는 이탈하고 획득비만 소진됩니다. 원장이 `validated` 에 근접하거나 최소한 `testing` 단계에서 손실이 없다는 근거가 생기면 재개.
> 아래 내용은 2026-06-30 합의 그대로 유지합니다.

**방향 (2026-06-30 합의)**: 개인용을 넘어 **개인 투자자용 AI 투자 리서치 플랫폼(SaaS)**. 포지셔닝은 "종목 찍어주는 봇"이 아니라 **리서치 플랫폼** — 전 구독자 동일·결정론적·설명가능·비개인화가 신뢰이자 법적 안전선(수익화 §6).
**North Star = 30일 리텐션 > 40%.** 결제·티어는 리텐션 >40% 검증 *후에만*. 시퀀스: **획득(A·B·D) → 리텐션 측정(C) → 인터뷰 → 결제(E)**.
인라인 `[승인][거절]` 버튼은 이미 구현됨 — `callback_query` 인프라를 약관 동의 "[동의합니다]" 버튼에 재사용.

### Phase A — 가입 모델 전환 + 약관/고지 (획득의 전제)
오너 수동 승인 → **셀프서비스 가입**. 가입과 약관 동의는 **법적으로 분리 불가 → 한 묶음**(수익화 §6).
- [ ] **가입 모델 = 옵션 B(토글)**: `BOT_OPEN_SIGNUP` 플래그(`src/config.py`). `false`(기본=현 베타)=소유자 승인 유지 / `true`=`/start`→약관 동의→자동 `active`. 상태모델 그대로, 오픈 모드는 pending 건너뜀.
- [ ] **약관/고지 동의 단계**: `/start` 에 disclaimer + 동의 게이트(`callback_query` "[동의합니다]" 버튼, 폴백 `/agree`). 동의 전엔 active 안 됨. → `src/subscribers.py` · `scripts/bot.py` · `src/notifier.py`.
- [ ] **고지 문구 상시 노출**: 다이제스트·`/stock` 응답 하단 한 줄 — **현재 `findings.DISCLAIMER` 로 이미 노출 중**, 약관 문구와 맞추는 일만 남음.
- [ ] **스키마 선반영**(`storage.add_column_if_missing`): `tier`(기본 'free') · `terms_accepted_at` · (후일)`expiry_date`. 나중 결제 도입 시 Turso 마이그레이션 충돌 회피(`CLAUDE.md §4.10 (9)`).

### Phase B — 설명가능성 자연어 레이어 (킬러 피처 · 신뢰)
점수의 "왜"를 자연어로. **신규 API 0콜 · LLM 0** — 기존 `detail` JSON + 결정론적 규칙. (다이제스트 🆕 종목의 `근거:` 줄이 이미 일부 구현: `digest.evidence_from_detail`)
- [ ] `format_stock()` 재작성: 숫자 분해 → "✅수익성 탁월(ROIC156%) · ✅밸류 매력적 · ⚠️배당 거의 없음" 식 사유. 규칙 예: GP>40%→"수익성 탁월", NetDebt/EBITDA<1→"레버리지 양호", earningsYield<0→"적자/밸류 경고".
- [ ] 동일 규칙을 마케팅 콘텐츠(종목 분석 글)로 재활용.

### Phase C — 활동 로깅 (리텐션 측정 — **데이터는 소급 백필 불가**)
- [ ] `last_active` 컬럼 + 일별 오픈/명령 이벤트(`src/subscribers.py`, `add_column_if_missing`).
- [ ] 30일 코호트 집계 스크립트(`scripts/`) — 리텐션 % 산출.

### Phase D — 획득 (랜딩 + 무료 콘텐츠)
- [ ] 정적 랜딩(`dashboard/landing.html`) + "무료 시작"(텔레그램 딥링크).
- [ ] 교육 콘텐츠 파이프라인(주간 국면 리포트 등).
- [ ] (선택) 워치리스트(`src/watchlists.py`) — "추적·정보 도구"(비개인화, 무료).

### Phase E — 결제·티어 (리텐션 >40% 검증 후에만)
- [ ] `tier` 분기 + `/upgrade` + 티어별 기능 게이팅(무료/Basic/Pro).
- [ ] Toss Payments + Cloudflare Worker(웹훅 분리 — Oracle OOM 회피) + `expiry_date` 만료 관리.
- [ ] 통신판매업 신고·사업자등록·부가세. 개인화 기능 도입 전 **한국 변호사 자문 필수**.

## 6. 사용자 작업 스타일 (요약 — 전문은 `CLAUDE.md §4`)
- **Strict phase-gate**: "다음 단계로" 명시 승인 전까지 다음 단계 코드 미리 짜지 말 것. (2026-10 수정 라운드는 사용자가 명시 승인한 예외였고, 끝나면 복귀)
- **시니어 엔지니어 리뷰 톤**: 의심스러운 코드는 비판적으로 짚고 대안 제시.
- **버그 발견 시 즉시 fix 는 OK** (phase-gate 예외) — 단 새 기능 추가가 아니라 기존 버그 수정일 때.
- **결정 사항은 옵션(A/B/C) 제시 후 명시적 승인 요청.** 한국어 응답. push 는 사용자 검토 후에만.
